# Architecture — modèle C4

## Niveau 1 — Contexte

```mermaid
C4Context
  title ShieldGate — diagramme de contexte
  Person(user, "Utilisateur", "Employé ou client d'une application de l'entreprise")
  Person(admin, "Administrateur", "Gère les comptes, les rôles et les clés API")
  System(sg, "ShieldGate", "Identité, autorisation et audit")
  System_Ext(apps, "Applications clientes", "Back-office, mobile, API partenaires")
  System_Ext(siem, "SIEM", "Analyse des événements de sécurité (v2)")

  Rel(user, sg, "Se connecte, gère sa MFA et ses sessions", "HTTPS")
  Rel(admin, sg, "Administre via la console", "HTTPS")
  Rel(apps, sg, "Délèguent l'authentification et les décisions d'accès", "HTTPS, clé API")
  Rel(sg, siem, "Exporte le journal d'audit", "Syslog / ECS")
```

## Niveau 2 — Conteneurs

```mermaid
C4Container
  title ShieldGate — diagramme de conteneurs
  Person(admin, "Administrateur")
  System_Ext(apps, "Applications clientes")

  System_Boundary(b, "ShieldGate") {
    Container(console, "Console", "Vue 3, Pinia, Vue Router", "SPA d'administration servie par Nginx")
    Container(api, "API", "Node.js 22, Fastify 5", "Authentification, sessions, MFA, PDP, audit")
    ContainerDb(pg, "PostgreSQL 17", "Relationnel", "Comptes, rôles, politiques, clés API")
    ContainerDb(mongo, "MongoDB 8", "Documents", "Journal d'audit (volume élevé, schéma souple)")
    ContainerDb(redis, "Redis 7", "Clé-valeur", "Sessions, compteurs d'échecs, limitation de débit")
  }

  Rel(admin, console, "Utilise", "HTTPS")
  Rel(console, api, "Appelle", "JSON, cookie de session + jeton CSRF")
  Rel(apps, api, "POST /v1/authorize", "Bearer clé API")
  Rel(api, pg, "Lit et écrit", "SQL paramétré")
  Rel(api, mongo, "Écrit par lots, interroge", "insertMany")
  Rel(api, redis, "Sessions et compteurs", "RESP")
```

## Niveau 3 — Composants de l'API

```mermaid
flowchart TB
  subgraph Transport [Plugins Fastify]
    headers[Helmet<br/>CSP, HSTS]
    limit[Rate limit<br/>Redis]
    csrf[CSRF<br/>Origin + jeton]
    authn[Authentification<br/>session ou clé API]
  end

  subgraph Modules
    auth[auth<br/>connexion, verrouillage, stuffing]
    sessions[sessions<br/>Redis, révocation]
    mfa[mfa<br/>TOTP RFC 6238]
    users[users<br/>politique de mot de passe]
    keys[api-keys<br/>HMAC + pepper]
    authz[authorization<br/>RBAC + ABAC]
    audit[audit<br/>tampon + MongoDB]
  end

  authn --> sessions
  authn --> keys
  auth --> users
  auth --> sessions
  auth --> mfa
  auth --> audit
  users --> audit
  keys --> audit
  authz --> audit
```

Chaque module expose des interfaces (`UserRepository`, `SessionStore`, `AuditSink`...) avec une
implémentation réelle (PostgreSQL, Redis, MongoDB) et une implémentation en mémoire pour les tests
rapides. Les tests d'intégration valident les implémentations réelles avec Testcontainers.
